# maze_escape — SLAM 기반 미로 탐색과 카메라 열쇠·문 제어

TurtleBot3가 SLAM 지도를 생성하고, 직접 구현한 프론티어 알고리즘으로 미지 영역을 자율 탐색하는 프로젝트입니다.
RGB-D 카메라로 열쇠 대용 물체를 인식·획득한 뒤 문을 열고 통과하여 `exit_marker`까지 이동합니다.

## 현재 진행 상황

| 기능 | 확인 상태 |
|---|---|
| 팀 미로에서 TurtleBot3 실행 | 우분투 VM에서 실행 확인 |
| SLAM 지도 생성 | 정상적으로 그려지는 것 확인 |
| Nav2 왕복 이동 | 두 목표 이동 성공 |
| 직접 구현한 프론티어 추출·선택·반복 탐색 | 목표 10개 연속 도착 성공 |
| RGB-D 카메라 영상 수신·열쇠 인식 | 우분투 VM·가제보에서 실행 확인 완료 |
| 열쇠 접근·획득·문으로 이동 | 통합 실행 확인 완료 |
| 문 열기·라이다로 문 열림 확인 | 통합 실행 확인 완료 |
| 막힌 접근점의 대체 후보·도착 후 카메라 재탐색 | 수정 구현 및 자동 검사 완료, 우분투 실행 확인 예정 |
| 열쇠 모델 삭제·문 통과·exit_marker 도착 | 수정 구현 및 자동 검사 완료, 우분투 실행 확인 예정 |
| 이전 객체 관측 위치 기억·우선 재확인 | 피드백 반영 및 자동 검사 완료, 우분투 실행 확인 예정 |
| Frontier 소진 후 기존 공간의 관측 지점 재방문 | 피드백 반영 및 자동 검사 완료, 우분투 실행 확인 예정 |

기존 버전은 현재 미로에서 **자율 탐색 → 카메라 열쇠 인식 → 접근·획득 → 문으로 이동 → 문 열림 확인**까지 통합 실행을 확인했습니다.
이번 수정본은 대체 접근점 선택과 재인식, 열쇠 모델 삭제, 문 통과 후 출구 도착까지 확장했습니다.
로직·설정 자동 검사 99개를 통과했으며, 이번 변경의 실제 가제보 통합 실행은 추가로 확인합니다.
탐색 목표 10개 도착은 반복 탐색의 검증 결과이며, 전체 영역 탐색률과는 구분합니다.

## 개발 환경

- Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic
- TurtleBot3 Burger / SLAM Toolbox / Nav2
- Python 3.12, NumPy, OpenCV, PyYAML
- VMware 기반 개발

## 설치와 실행

ROS·가제보·TurtleBot3 패키지가 설치된 우분투에서 실행합니다.
저장소 폴더를 `~/maze_escape`로 두면 상세 안내의 경로를 그대로 사용할 수 있습니다.
실행 스크립트는 실제 프로젝트 폴더 위치를 자동으로 찾습니다.

```bash
cd ~/maze_escape
bash setup.sh
```

`setup.sh`는 설치된 패키지를 확인하고, 프로젝트의 `models/camera_burger` 안에 RGB-D 카메라 로봇을 생성합니다.
설치된 로봇 모델과 바퀴·마찰·주행 물리 설정은 유지합니다.

각각 별도 터미널에서 실행하며, 앞 단계가 준비된 뒤 다음으로 진행합니다.

| 터미널 | 명령 | 역할 |
|---|---|---|
| 1 | `bash run/01_sim.sh` | 가제보 미로·카메라 로봇·센서 연결 |
| 2 | `bash run/02_slam.sh` | SLAM 지도 생성 |
| 3 | `bash run/03_nav2.sh` | 자율 이동 |
| 4 | `bash run/04_rviz.sh` | 지도·로봇·카메라 화면 |
| 5 | `bash run/05_probe.sh` | 짧은 왕복 이동 시험 |

왕복 시험을 통과하면 같은 터미널 5에서 아래 프로그램 중 하나를 실행합니다.

```bash
# 프론티어 표시 확인: 종료할 때 Ctrl+C
bash run/06_frontiers.sh

# 프론티어 자동 탐색만 시험
bash run/07_explore.sh

# 카메라로 열쇠 획득·문 통과 후 출구까지 이동
bash run/08_camera_escape.sh
```

06·07·08은 한 번에 하나씩 실행합니다. 자세한 준비·종료 방법은 아래 문서를 참고하세요.

- [처음 실행하기](처음_실행하기.md)
- [카메라 열쇠 인식과 문 열기](카메라_열쇠와_문_실행하기.md)
- [출처와 검사 범위](출처와_검사.md)

## 카메라 임무

현재 미로는 **노란색 블록을 열쇠 대용 물체**, **빨간색 벽을 문**, **초록색 블록을 출구 표식**으로 사용합니다.
열쇠 물체의 모델 이름은 `red_key`이지만 실제 표시 색상은 노란색이며, 영상 인식은 이 색상을 기준으로 합니다.

RGB-D 영상의 색상·깊이, 카메라 보정 정보, SLAM 좌표를 이용해 접근 위치를 계산합니다.
열쇠 가까이에 도착해 영상을 다시 확인한 후 가제보에서 열쇠 모델을 삭제해 획득을 처리합니다.
삭제 후 새 카메라 영상 세 장에서 열쇠가 사라진 것을 확인해야 획득 기록을 저장합니다.
획득을 확인해야 문 열기가 가능하며, 문은 위로 들어 올리는 방식으로 열립니다.
문 이동 명령의 응답과 함께 라이다에서 통과할 공간이 비었다는 것을 확인합니다.
최신 지역 이동용 지도와 Nav2 충돌 검사를 이용해 문을 통과하고, 카메라로 초록색 `exit_marker`를 찾아 접근합니다.
`exit_marker` 도착을 카메라와 거리로 확인해야 임무를 완료합니다.

현재 미로의 색상 규칙을 이용하는 인식 방식이며, 인식 입력은 카메라 영상입니다.
다양한 열쇠 형태를 학습한 객체 검출 모델과는 구분됩니다.
접근 목표가 막히거나 아직 미확인일 때 주변의 연결된 빈 공간을 검사합니다.
물체 가까이에 유효한 접근점이 없으면 관측용 중간 목표로 이동하고, Nav2가 경로를 거절하면 다른 후보를 선택합니다.
도착 후 물체를 다시 인식하지 못하면 짧은 회전과 재접근을 수행합니다. 재확인 대기는 새 영상 수와 가상 시간, 실제 시간 한도를 함께 사용합니다.

## Frontier 소진 후 카메라 추가 탐색

지도 생성과 객체 관측 완료를 별도로 다룹니다. Frontier 후보가 없거나 Frontier 이동 한도에 도달해도,
카메라 임무는 곧바로 종료하지 않고 다음 순서로 목표물을 다시 찾습니다.

1. 이전에 카메라로 객체를 확인했던 **로봇의 관측 위치**를 우선 재방문합니다.
2. 재확인할 기억이 없으면, 이미 지도에 표시된 도달 가능한 빈 공간에서 관측 지점을 선택합니다.
3. Nav2로 관측 지점에 이동하고 회전하면서 새 카메라 영상을 확인합니다.
4. 현재 영상에서 목표물을 다시 확인하면 기존 이동·회전의 종료를 확인한 뒤 접근 목표로 전환합니다.

이전에 본 좌표만으로 열쇠를 획득하거나 문을 열지 않습니다.
관측 위치·지도 좌표계·최근 관측 시각을 함께 기억하고, 새 카메라 관측으로 재확인합니다.
관측을 마친 지점과 이동에 실패한 지점을 기록해 반복 방문을 줄입니다.
관측 완료 판정에는 새 영상 수와 회전 중 확인한 방향도 사용합니다.

추가 관측은 목표물별 기본 16회로 제한하며, 한도 초과나 관측 후보 소진 시 이유를 기록하고 실패로 종료합니다.
이를 전체 공간에 객체가 없다는 판정으로 해석하지 않습니다. 프로그램을 다시 실행하면 임무 내 기억은 초기화됩니다.

```bash
# 필요하면 관측 재방문 한도를 지정할 수 있습니다.
bash run/08_camera_escape.sh --inspection-goals 24
```

최신 수정본 적용·재실행: [팀 피드백 반영 업데이트](피드백반영_재탐색_업데이트.md).

## 임무 로그

08번 카메라 임무는 발견·접근·획득·문 통과·완료와 오류·재시도를 중심으로 출력합니다.
이동 진행은 15초 간격으로 표시하며, 좌표와 후보 검사 등 자세한 기록은
`logs/session_*.jsonl`에 저장합니다. 가제보와 Nav2 등 다른 실행 프로그램의 로그는 별도로 출력됩니다.

## 검사

프로젝트 폴더에서 실행합니다.

```bash
python3 -m unittest discover -s tests -v
```

검사는 지도 좌표·프론티어·경로 판정, 비동기 요청 취소, 영상 색상·깊이·좌표 변환,
열쇠 없는 문 열기 차단, 문 열림 확인과 설정의 일관성을 검증합니다.

`logs/`와 카메라 로봇 생성물, 개인 백업·업데이트 압축 파일은 Git에서 제외합니다.
ROS 통신은 `ROS_DOMAIN_ID=26`, 가제보 통신 공간은 `maze_escape`를 사용합니다.
